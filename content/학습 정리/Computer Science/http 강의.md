status code
- 200 ok
- 301, 302, 307=302, 308=301 페이지 이동, 리다이렉트, 
	- 301 영구적 이동, 앞으로 계속 다른 곳으로 보내
		- 301과 함께 location: b.com -> 바로 b.com으로 클라이언트 요청을 보냄. 근데 301의 경우 이 플로우가 지나면 클라이언트가 내부적으로 다시 요청을 보내야 하는 경우에 앱 삭제후 재설치할때까지 b.com으로 보내게 됨.
	- 302 found, moved temporaly 임시적 이동
		- 앱을 껐다 키면 다시 a.com으로 보내게 됨.
	- 301은 절대 쓰지 말고 302만 쓰기

SSL pinning
프록시를 보면 
CONNECT 단계에서 에러가 뜨면 SSL Pinning의 적용
SSL 중간에 프록시가 끼게 되면
프록시를 설치할 때 사설인증서를 추가하고 신뢰설정을 하면 중간에 인증서가 바뀜
SSL Pinning -> 서버에 SSL 인증서를 둘 것임(A) 클라이언트에서는 클라이언트를 배포할 떄 A에 대한 정보를 넣음. 그럼 중간에 프록시가 끼게 되면 B라는 인증서로 B라는 SSL 인증서가 오고, 클라이언트는 이에 대해 오류를 띄우게 함.
앱을 배포했을 때 앱의 생성 주기는 인증서의 유효기간과 같다.
