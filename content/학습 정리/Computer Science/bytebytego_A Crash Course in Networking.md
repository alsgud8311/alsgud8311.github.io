## 개요
해당 글에서는 `네트워크 엣지, 엑세스 네트워크, 네트워크 코어, 네트워크 프로토콜, 인터넷 프로토콜 스택`과 같은 핵심적인 네트워크 컴포넌트들에 대해서 정리한다.

## 인터넷의 진화
인터넷을 몇십년동안 계속해서 중간중간 큰 변화를 가지고 오는 개발이나 혁신을 주기적으로 가지면서 진화해 왔다.

![](https://i.imgur.com/80e2IVT.png)


## 인터넷의 컴포넌트들
인터넷은 여러 핵심 네트워크 컴포넌트들을 통해 작동한다. 
### 네트워크 엣지
인터넷에 연결되어 있는 컴퓨터나 다른 디바이스들은 `종단 시스템(end system)` 으로 알려져 있다.
이는 이러한 장치들이 결국에는 네트워크의 종착지로 많이 쓰이기 때문에 이는 곧 인터넷의 edge, 즉 가장자리에 위치해있기 때문이다. 네트워크 가장자리에 있는 종단 시스템에는 데스크탑 컴퓨터, 서버, 모바일 장치, 그리고 스마트 가전이나 IoT 장치와 같은 비전통적인 "사물"들이 포함된다.

이러한 종단 시스템은 웹 브라우저, 웹 서버, 이메일 클라이언트 또는 이메일 서버와 같은 애플리케이션 프로그램을 호스팅하기 때문에 **호스트(hosts)** 라고도 불린다.

이 호스트는 다시 **클라이언트**와 **서버**로 나뉘어질 수 있다. 
- 클라이언트는 일반적으로 데스크탑 및 모바일 PC, 스마트폰과 같은 개인 디바이스를 의미
- 서버의 경우 주로 웹 페이지를 저장하고 배포하고, 비디오를 스트리밍하고, 이메일을 중계하는 등의 서비스를 제공하는 더 강력한 장치를 의미

### 엑세스 네트워크
액세스 네트워크는 종단 시스템(end system), 즉 아까 말했던 인터넷의 가장자리에 위치한 컴퓨터 및 기타 장치들을 경로상의 **첫 번째 라우터(edge router)** 에 물리적으로 연결하는 네트워크로, 종단 시스템과 더 넓은 네트워크 인프라 사이의 중요한 링크의 역할을 담당한다.

이를 통해 액세스 네트워크는 최종 사용자(end-users)와 인터넷 사이의 **최종 연결(last-mile connectivity)** 을 제공하는데, 이러한 액세스 네트워크는 크게 세 가지로 카테고리화 될 수 있다.

![](https://i.imgur.com/BTgtXYG.png)
- 홈액세스 네트워크(Home Access Networks): 주거 환경 내에서 연결성과 통신을 가능하게 하는 기술 집합으로, 집 안의 장치들이 인터넷에 연결하고, 데이터를 공유하며, 서로 통신할 수 있도록 해줌


![](https://i.imgur.com/HLfy4UP.png)
- 기관 액세스 네트워크(Institutional Access Networks): 조직, 기관 및 기업이 인터넷에 연결하고 구내에서 통신을 용이하게 하기 위해 사용하는 네트워킹 인프라 및 기술. 대규모 운영의 특정 요구 사항 및 필요를 처리하도록 설계됨





![](https://i.imgur.com/gN2tI6L.png)
- 모바일 액세스 네트워크(Mobile Access Networks): 스마트폰, 태블릿과 같은 모바일 장치가 인터넷에 연결하고 서로 통신할 수 있도록 하는 다양한 기술. 모바일 사용자를 위한 무선 통신 및 데이터 전송을 촉진

이런 유저-인터넷간 종단으로 제공하는 연결성을 제공하기 위해서는 각 네트워크에 따라 여러 기술이 사용된다.
![](https://i.imgur.com/xgqDCWE.png)
## 네트워크 코어
네트워크 코어는 인터넷의 핵심 부분으로, 인터넷의 최종 시스템들을 상호 연결하는 패킷 라우터와 링크의 망이다.

![](https://i.imgur.com/YIr04TP.png)

네트워크 코어는 패킷 스위칭을 기반으로 작동한다.

> 패킷 스위칭(Packet Switching)
> 데이터를 관리 가능한 블록 또는 패킷으로 나누어 디지털 네트워크에서 데이터를 전송하는 방법

이는 곧 최종 호스트가 애플리케이션 메시지를 데이터 chunk로 나누고 이를 패킷 안에 넣어 인터넷으로 보내는 것이다.
이 과정에서 각 패킷은 목적지 주소를 포함하고 네트워크를 통해 독립적으로 라우팅된다. 이를 통해 여러 통신 세션이 코어 네트워크를 공유할 수 있도록 해준다.

대표적인 예를 통해 설명하자면
 - 웹 서버는 애플리케이션 응답을 패킷으로 분해
 - 서버는 이 데이터 패킷을 보냄
 - 패킷은 인터넷 백본 링크를 통해 라우터에서 라우터로 이동하며 최종 목적지인 사용자 노트북의 브라우저에 도달할 때까지 이동
 - 노트북은 패킷을 재조립하여 웹 서버의 응답을 재구성
위와 같은 예시를 통해 어떻게 패킷으로 나누어지고 종단까지 전달되는지 알 수 있다.

이러한 기능을 가능하게 해주는 네트워크 코어 내부의 두 가지 핵심 기능은 포워딩과 라우팅이다.

### 포워딩
![](https://i.imgur.com/u0EiTN6.png)
- 라우터의 입력 링크에서 해당 라우터 출력 링크로 도착하는 패킷을 이동시키는 지역적 동작
- 인터넷에 있는 수백만 대의 라우터 각각 내부에 있는 포워딩 테이블에 의해 제어됨
등의 특징이 있다.

패킷이 도착하면 라우터는 패킷에 담겨 있는 목적지 주소를 확인하고 위에서 말한 포워딩 테이블에서 해당 주소를 찾는다. 그런 다음에 이 패킷을 목적지로 향하는 출력 링크로 전송하는 것이 포워딩이다.

### 라우팅
![](https://i.imgur.com/y3z1qHO.png)
- 소스에서 목적지까지 패킷이 이동하는 전체 경로를 결정하는 전역적 프로세스
- 전역 네트워크 상의 두 지점 사이에서 가장 효율적인 경로를 계산하고, 네트워크 상태와 트래픽 흐름을 고려한 최적 경로 알고리즘을 통해 경로 결정
의 특징을 가지는 라우팅은, 적절한 경로를 결정하고 각 라우터의 포워딩 테이블을 네트워크 목적지에 효율적으로 도달하기 위한 다음 홉으로 채운다.

이러한 기능을 하는 네트워크 코어는 인터넷의 핵심으로서 패킷의 이동을 전체적으로 관리한다.

## 네트워크 프로토콜
네트워크 프로토콜은 네트워크 장치 간 모든 통신 활동을 관리하는 표준 규칙을 제공한다. 대표적인 에로 메시지 형식, 메시지 교환 순서, 그리고 예상되는 응답을 정의하는 등에 대한 규칙을 통해 장치 간 적절한 통신을 가능하게 하면서 네트워크 내의 모든 활동을 조정한다.

- 물리적으로 연결된 두 네트워크 인터페이스 카드 간 비트 전송을 제어하는 하드웨어 레벨의 프로토콜
- 최종 시스템 간 패킷 전송 속도를 조절하는 혼잡 제어 프로토콜
- 각 패킷이 출발지에서 목적지까지 이동해야 하는 경로를 매핑하는 라우팅 프로토콜
등이 모두 네트워크 프로토콜에 속한다.

이러한 네트워크 프로토콜의 흔한 예는
- TCP (Transmission Control Protocol): 신뢰할 수 있는 데이터 전송 지원
- IP (Internet Protocol): 논리적 주소 지정을 담당합니다2.
- HTTP (Hypertext Transfer Protocol): 웹 트래픽 구조를 정의
- FTP (File Transfer Protocol): 파일 전송을 위한 프로토콜
등이 있으며, 각각의 프로토콜들은 신뢰할 수 있는 데이터 전송, 주소 지정, 라우팅, 다양한 유형의 네트워크 서비스 관리 등 네트워크 내에서 특정 목적을 수행한다.

이러한 프로토콜들에 대한 표준화는 IETF(Internet Engineering Task Force)에서 RFC(Request For Comments)를 발행하면서 이 RFC의 기준을 지켜 개발함으로써 다양한 하드웨어나 소프트웨어의 구현 과정에서 상호 운용성을 가질 수 있도록 한다.

## 인터넷 프로토콜 스택(TCP/IP 스택)
음청 복잡하고 수많은 애플리케이션과 프로토콜, 다양한 종단 시스템, 패킷 스위칭 등 다양한 복잡성들이 주어지는 인터넷에서 네트워크 아키텍처를 효율적으로 구성하는 방식은 **계층화**이다.

네트워크를 설게하는 과정에서 프로토콜과 프로토콜을 구현하는 네트워크 하드웨어 및 소프트웨어를 계층화한다. 이 과정에서 각 프로토콜은 이 계층들 중 하나에 속한다.
각 계층은 
- 해당 계층 내에서 특정 작업을 수행
- 바로 아래 계층의 서비스를 사용하여 서비스를 제공
한다.

TCP/IP 스택으로 알려져 있는 인터넷 프로토콜 스택은 인터넷 및 대부분의 컴퓨터 네트워크를 통해 통신에 사용되는 프로토콜을 표준화하는 개념적 프레임워크이다. 장치들이 서로 통신하고 데이터를 교환할 수 있게 해주는 네트워크 프로토콜의 집합이며, TCP/IP 모델은 OSI 모델에서 4개의 계층이 포함된다.


![](https://i.imgur.com/UegbpIr.png)
### 애플리케이션 계층(Application Layer)
- 최종 사용자 또는 애플리케이션에 직접 네트워크 서비스를 제공하는 역할
- 높은 수준의 통신 및 사용자 인터페이스를 다룸
- HTTP, FTP, SMTP, DNS 등의 프로토콜.

### 전송 계층(Transport Layer)
- 장치 간의 종단 간(end-to-end) 통신을 담당
- 서로 다른 장치의 애플리케이션 간에 데이터가 신뢰할 수 있고 효율적으로 전송되도록 함
- 신뢰할 수 있는 연결 지향 통신을 제공하는 TCP / 더 빠르고 연결 없는 통신을 제공하는 UDP 등

### 네트워크 계층(Network Layer)
- IP (Internet Protocol)가 위치하는 곳
- 서로 다른 네트워크의 장치 간에 데이터 패킷의 주소 지정 및 라우팅 처리
- 주로 모든 인터넷 구성 요소에 필수적인 IP 프로토콜을 포함
- 데이터그램이 출발지와 목적지 사이에서 취하는 경로를 결정하는 라우팅 프로토콜도 포함
- IP는 인터넷을 하나로 묶는 역할을 하기 때문에 종종 단순히 IP 계층이라고도 불림
- IPv4와 IPv6

### 링크 계층(Link Layer)
- 네트워크 인터페이스 계층 또는 데이터 링크 계층이라고도 하며, 동일한 네트워크 세그먼트 상의 장치 간의 물리적 연결을 담당
- MAC(Media Access Control) 주소와 같은 프로토콜 및 하드웨어 주소 지정을 다룸
- 이더넷(Ethernet)은 이 계층에서 흔히 사용되는 프로토콜입니다
