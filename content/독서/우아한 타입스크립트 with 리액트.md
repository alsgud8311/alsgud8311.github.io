### 키워드 노트
- 폴리필: 브라우저가 지원하지 않는 코드를 브라우저에서 사용할 수 있도록 변환한 코드 조각이나 플러그인
- 트랜스파일: 최신 버전의 코드를 예전 버전의 코드로 변환하는 과정
- 컴포넌트 베이스 개발(Component Based Development): 재사용할 수 있는 컴포넌트를 개발 또는 조합하여 하나의 애플리케이션을 만드는 개발 방법론
- 슈퍼셋(superset): 기존 언어에 새로운 기능과 문법을 추가해서 보완하거나 향상하는 것. 슈퍼셋 언어는 기존 언어와 호환되며 일반적으로 컴파일러 등으로 기존 언어 코드로 변환되어 실행됨
- 덕 타이핑: 어떤 함수의 매개변숫값이 올바르게 주어진다면 그 값이 어떻게 만들어졌는지 신경쓰지 않고 사용하는 방식
- 트리쉐이킹(tree-shaking): JS,TS에서 사용하지 않는 코드를 삭제하는 방식으로, 번들링 과정에서 사용하지 않는 코드의 경우 자동으로 삭제됨. 웹팩이나 롤업같은 모듈 번들러를 사용해서 트리쉐이킹을 함.
- 호출 시그니처(Call Signature): 타입스크립트에서 함수 타입을 정의할 때 사용하는 문법. 함수 타입은 해당 함수가 받는 매개변수와 반환하는 값의 타입으로 결정된다. 호출 시그니처는 이러한 함수의 매개변수와 반환 값의 타입을 명시하는 역할을 한다.


값에서 사용된 typeof는 자바스크립트 런타임의 typeof 연산자가 되어 7가지 데이터 타입(boolean, null, undefined, Number, BigInt, String, Symbol, Function)을 나타냄
타입에서 사용된 typeof는 값을 읽고 타입스크립트 타입을 반환

타입스크립트 코드는 자바스크립트로 변환되고 타입스크립트의 타입 시스템과 문법은 컴파일 ㄱ단계에서 제거된다. 따라서 as라는 타입 단언을 통해 타입을 강제할 수 있지만 런타임에서는 효력을 발휘하지 못한다.


ts-config에서 strictNullChecks 옵션 활성화 -> 사용자가 명시적으로 해당 타입에 Null이나 undefined를 포함해야만 사용 가능


object 타입을의 경우 가급적 사용하지 말도록 권장되는데 나중에 다룰 any 타입과 유사하게 객체에 해당되는 모든 타입 값을 유동적으로 할당할 수 있어 정적 타이핑의 의미가 크게 퇴색되기 때문이다.
객체, 배열, 정규표현식, 함수, 클래스 등 모두 object 타입이라는 큰 범주로 묶이기 때문에 호환된다.

빈 객체 타입을 지정하기 위해서는 {}보다 유틸리티 타입으로 Record<string, never>로 사용하는게 바람직하다

타입스크립트에서는 튜플 타입도 대괄호로 선언하는데, 배열과 유사하지만 튜플의 대괄호 내부에는 선언 시점에 지정해준 타입 값만 할당할 수 있다. 따라서 선언하지 않은 속성 할당이나 선언한 속성을 할당하지 않을 경우 에러가 발생한다.


any타입과 unknown 타입의 비교

| any 타입                                                          | unknown 타입                                                            |
| --------------------------------------------------------------- | --------------------------------------------------------------------- |
| - 어떤 타입이든 any 타입에 할당 가능<br>- any 타입은 어떤 타입으로도 할당 가능(never를 제외한) | - 어떤 타입이든 unknown 타입에 할당 가능<br>- unknown 타입은 any 타입 외에 다른 타입으로 할당 불가능 |

enum의 효과
- 타입 안정성: 명시되지 않은 다른 문자열은 인자로 받을 수 없음
- 명확한 의미 전달과 높은 응집력: 다루는 값이 무엇인지 명확하고 이에 따른 응집력이 뛰어남
- 양방향에서 값에 접근 가능
- 가독성 : 응집도가 높기 때문에 말하고자 하는 바가 명확하여 쉽게 이해가 가능
- 주의할 점
	- 숫자로만 이루어져 있거나 타입스크립트가 자동으로 추론한 열거형은 안전하지 않은 결과를 낳을 수도 있음 -> `const enum`으로 열거형을 선언하게 되면 역방향의 접근을 허용하지 않아 자바스크립트에서 객체에 접근과 유사한 동작을 보장
	- 즉시 실행 함수(IIFE) 형식으로 변환되지만 즉시 실행 함수로 변환된 값을 사용하지 않는 코드로 인식하지 못하는 경우가 있어 `const enum`이나 `as const assertion`을 사용하여 열거형과 동일한 효과를 얻는 방법이 있음
